# 简历效果评测协议 v1（2026-09-24）

## 目标与事实起点

用户确认：简历中的 84%→94%、62%、76%→88%、12→3、24→32、2.8→2.1、9/12 均为拟写目标，没有原始实验记录。它们不是既有成果，也不是评测通过阈值。目标是得到可复现、可解释的实测结论，再据此修改简历。

当前不使用 Jev；路由对照必须称为规则、规则加 DeepSeek 回退、DeepSeek 直接解析。构造输入的真实 API 实验可以报告为离线构造集实验，但不能称为真实用户测试或独立人工标注。

## 实验清单与完成条件

| --- | --- | --- | --- | --- |

规模是采集目标，不为凑数复制改写同一题。相同语义或同一素材衍生任务必须标记 family_id；统计时说明相关性，不把它们当独立用户。

## 执行次序

用户进一步要求集中一至两个亮点，并扩大样本而非用二十余条开发题替代原定规模。本轮优先完成路由 200 条与检索 100 条；其余三项保留工程证据，暂不作为本轮效果提升主张。题库为明确披露的 Agent 构造集，全部标签待人工审核；不会将构造输入冒充真实用户数据。

1. 先用 30 条新构造路由题校准标注规范和输出链路。候选标签由 Agent 起草，人工标签留空；本阶段一律为 pilot，不参与正式 200 条统计。
2. 审核规范后制作正式题库。记录来源、作者、审核者、歧义与修订；模型预测不展示给标注者。人工复核不把构造集变成真实用户数据。
3. 正式运行前冻结输入、标签、代码和依赖快照及 SHA256；建立可执行命令和模型名称记录。题库不能与已见开发题按字符串或语义重复。
4. 先测基线再分析，实验执行顺序交错以降低时段差异；保存每次请求、响应、失败、工具调用、布局与产物。私有凭证不进入证据。
5. 正式集一旦用于调优即转为开发集；修改后采用新的未见预留集验收。复测不得覆盖旧结果，也不挑最好一次。
6. 有随机性的任务预先指定重复次数；报告每次结果及范围。独立任务不足时不使用狭窄置信区间营造确定性。小样本不推广为生产效果。
7. 交付数据说明、逐条结果、失败清单、可复现命令、指标计算、对照限制及对应简历表述。无收益与退化同样是有效结论。

## 指标约束

- 模型调用减少率 = 1 - 混合组实际调用总次数 / 全模型组实际调用总次数；不等同于 token 成本减少率。失败、重试均计入调用；同时报告质量差异。
- 记忆确认不匹配不得计为治理成功；除了错误写入，也必须报告应更新而未更新，避免“什么都不写”得到好成绩。
- 决策轮数必须带分母；仅在不同成功子集上比较均值可能产生选择偏差，须补充共同成功任务及全部未解决任务。
- 检索未命中、路由失败、工具异常不从分母删除。基础库仅 14 张审核卡时应报告这一规模，不能推广到企业级大知识库。
- 扩展动作成功不等于最终海报达标；同时满足精确目标、事实、锁定和必要可读性要求才计任务成功。
- 当前脚本不是全部最终可用：路由需补充宏 F1/类别与调用异常审计；记忆需实际候选审核导入；正式统计需补充配对不确定性和数据来源检查。这些必须在最终报告前完成。
