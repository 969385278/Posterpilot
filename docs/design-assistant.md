# 海报设计问答助手

## 定位与用法

助手在 PosterPilot 创作工作台下方。没有海报时可以问设计知识；生成或打开任务后，可以围绕当前海报提问。PosterHub 继续提供已审核案例，不再增加独立聊天项目或另一套生成服务。

示例：先问“为什么标题不够醒目？”，查看回答、工具记录及参考依据，再讨论“保留主视觉，优先增强标题层级”。助手若提出可执行建议，会展示完整修改要求；点击“确认修改这张海报”后才消耗一次现有优化轮次。也可以不确认，继续讨论。

## 实现对应

- `apps/api/app/services/design_assistant.py`：独立的受约束 ReAct 问答循环，复用现有文本与视觉 Provider。不是新增 LangGraph 子图，不修改原生成图。最多四次只读工具调用、五次模型请求，整体超时 100 秒，单工具超时 25 秒。
- `apps/api/app/schemas/assistant.py`：输入、结构化模型决策、引用、工具轨迹与修改建议的校验。
- `apps/api/app/persistence/assistant_repository.py`：SQLite 保存问题、回答、引用、工具记录、关联任务及建议。每次只把最近三轮问答送入上下文，每条旧回答最多 2000 字符；这不是自动摘要或长期用户画像。
- `apps/api/app/api/routes/assistant.py`：提问、读取对话、确认建议接口。
- `apps/web/src/features/assistant/DesignAssistant.tsx`：工作台问答界面、依据展开、错误与等待状态、明确确认按钮。切换任务清空前端对话，避免混入其他海报。
- `apps/web/src/api/assistant.ts`：前后端请求封装。

## 五个只读工具

| 工具 | 来源与用途 |
| --- | --- |
| search_knowledge | 复用 KnowledgeRetriever；只显示已审核卡片，无向量结果时尝试词法匹配，并保留降级标记 |
| search_cases | 复用 PosterHub 的审核检索与质量检查，排除当前任务，默认不消费离线案例 |
| inspect_poster | 读取当前任务已保存的评测、结构化布局与设计分析 |
| analyze_image | 把当前任务已登记的海报图片交给视觉 Provider，围绕具体问题分析，不接受外部任意图片路径 |
| read_history | 读取当前任务的优化轮次与工具记录，不把得分上涨推断为用户接受 |

模型只能引用本轮工具返回的来源 ID；不存在的引用不会进入来源列表。工具结果作为资料提供，不赋予执行权限。提示词防注入并不保证模型在任意攻击下绝对安全；实际修改仍受既有白名单、参数校验和设计锁定约束。

## 修改边界

支持文字排版、非主视觉布局、整体背景色彩处理。不能修改活动事实、任意局部重绘人物或重新生成主视觉。不支持的请求应建议新建生成任务。

问答接口不调用修改工具。确认接口从服务端已保存的建议读取修改要求，复用 RunService.begin_decision 和 resume，进入原有持久化 LangGraph 任务。建议绑定提问时的任务和轮次；任务已运行、轮次变化、达到三轮上限时不能确认。重复确认由原业务状态机拒绝，不会重复启动优化。

## 配置与验证

沿用 `.env.example` 中现有 DeepSeek 文本模型、Ark 视觉模型和知识库配置，无新增密钥。真实运行入口仍为 `app.main:app`。离线演示明确返回“未调用问答模型”，不伪造模型答案或可执行建议。
