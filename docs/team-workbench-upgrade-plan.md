# PosterPilot / DesignHub 小型宣传团队工作台升级方案

日期：2026-09-19

状态：需求与范围设计。本文描述拟实施内容，不代表功能已经完成。本轮仅核查仓库、形成方案，未调用付费模型，未修改业务代码。

## 1. 已确认的需求

- 服务对象是一个小型宣传团队，有几位可参与试用的用户。
- 最突出的问题是标题缺少手绘海报字的表现力；普通宋体、黑体式叠字不能满足期望。
- 时间不是主要限制，后续真实模型调用累计预算不超过人民币 50 元。
- 求职目标是 AI 应用 / Agent 开发方向，希望用真实业务实现、工程取舍和验证成果说明能力。
- 其他范围由实施方判断。当前先明确方案，后续按验收阶段推进。
- 试用人数、真实活动资料和具体视觉偏好尚未采集；不得预写试用结果、落地规模或提升百分比。

## 2. 产品目标与范围

帮助宣传团队把活动信息制作成风格合适、信息准确、经过审核且可复用的宣传海报。

采用一个仓库、一个工作台、两个有清晰职责的模块：

| 模块 | 职责 | 用户能够完成的事 |
| --- | --- | --- |
| PosterPilot | 生成、分层修改、校验及人机协作 | 制作艺术标题，保留活动事实，独立修改标题或正文，查看版本差异 |
| DesignHub | 活动、知识和素材的治理 | 维护活动事实，审核知识与成品，发布正式版，查询可用素材，处理改期和撤回 |

简历是否分成两个项目条目，等实现完成后按各自深度决定；明确说明关联与共同来源，不把同一套实现重复包装。

核心流程：活动建档 → 选用已发布知识 → 生成与修改 → 提交审核 → 退回或发布 → 查询复用 → 活动变化后失效与重新发布。

第一版维持竖版活动海报，选取少量有明显区别的艺术标题风格。优先考察毛笔书写、粗笔手绘、轻松手写三类，最终保留哪些风格由样例效果和试用反馈决定。

第一版不扩展复杂组织树、多租户、自定义权限系统、无限画布、模型微调、多 Agent、社交平台自动发布。活动问答入口放到核心试用通过之后，按实际查询需求决定。DeepGaze 保持可选，不作为审美结论或主要验收指标。

## 3. 当前实现的事实与缺口

### 3.1 艺术标题

- 已内置 6 款 OFL 字体，本轮确认字体文件存在；已有前端选择、预览和后端渲染链路。
- `auto` 在选择案例字体维度时沿用案例映射；当前映射仅有 serif / sans / sans_bold，落到宋体、微软雅黑等常规字体。
- 缺文件或缺字会使整个标题回退为常规粗体。不能由代码存在这种路径推断某次用户实际遇到的原因，具体运行需要查看渲染记录。
- 设计提示明确要求主视觉不含文字；标题由 Pillow 统一排字，布局模型缺少艺术标题素材、字形构图和独立图层的业务描述。
- 当前图像 Provider 没有透明输出或遮罩编辑的可靠契约，默认配置使用 JPEG。生成透明标题、保留文字准确性、抠图边缘质量均需单独验证。

依据：`apps/api/app/poster/font_catalog.py`、`reference_adapter.py`、`renderer.py`，`apps/api/app/agent/prompts/design.py`，`apps/api/app/schemas/layout.py`，`apps/api/app/providers/image/ark.py`。

### 3.2 团队与数据治理

- 已有受约束 ReAct、HITL、任务级产物、引用及轮次记录。
- 知识卡已有审核状态和来源约束，数据目前以文件读取为主；已审核内容通过全量重建写入索引。
- 尚缺团队活动版本、成品审核、正式素材有效性、知识发布批次和可恢复的索引发布流程。
- 已有历史生成与优化案例说明及图片，但本轮未重跑。历史案例前后评测信号不同，不能将综合分变化视为净效果提升。

依据：`apps/api/app/rag/models.py`、`repository.py`、`indexer.py`，`apps/api/app/services/artifact_service.py`，`docs/demo/golden-demo-red-mansion.md`。

## 4. 第一优先级：艺术标题与可修改海报

### 4.1 分层设计

海报包含背景主视觉、艺术标题、活动信息三类独立内容。原始活动事实独立存储，不能从生成图片反推为权威数据。

标题资产至少关联目标文字、内容摘要、制作方式、风格参数、来源、文件校验值、版本和校对记录。图层移动、缩放、替换不要求重新生成背景。

| 修改 | 预期行为 |
| --- | --- |
| 修改时间或地点 | 更新活动修订和信息层，复用标题及背景，成品需重新审核；默认不调用生图 |
| 修改标题文字 | 创建新活动修订，使旧标题匹配与校对记录失效，重新制作或替换标题资产 |
| 修改标题风格 | 新建标题资产版本，保留背景与活动事实；重新审核最终成品 |
| 调整标题位置或大小 | 只修改组合参数；触发版面检查与成品审核，不自动重新生图 |

生成式标题是位图资产，可移动、缩放、替换；不宣称能像文本框一样逐字无损修改。短艺术标题可以与完整活动名称分开表示，但新增展示文案必须由用户确认，不能自动改写活动名称。

### 4.2 两种标题制作方式，共用资产与审核流程

1. 可控艺术排版：基于合法字体，增加有限的逐字错落、倾斜、大小变化、轮廓纹理与构图预设。保持准确文字和参数可编辑，作为低成本方案；不能将其描述为任意手绘字生成。
2. 生成式标题：用准确标题和受控风格生成独立短标题素材，探索字形参考约束和去背景处理；允许人工制作素材导入。先用有限样例判断可用性，再决定正式接入方式。

不以整张含字海报生成作为主生产路径，以保留时间地点的准确性与独立修改能力。

艺术字校验同时检查目标文本、缺字、多字、错字、可辨认程度、背景分离边缘、标题与画面的搭配。OCR / 视觉模型只提供辅助结果；审核者逐字确认后才允许发布。

回退必须在预览和版本记录中可见。发生缺字或生成失败时，让用户选择保留、替换或重做，不能静默回到粗体并标记艺术标题成功。

### 4.3 第一阶段验收门

- 冻结 6～8 份需求作为初步验收，包含短标题、较长标题、生僻字及数字标点；开发调参样例和保留验收样例分开。
- 在相同背景、活动事实和主要版式下对比当前标题、可控艺术排版和生成式标题；保留失败与淘汰候选。
- 请现有试用者分别评价文字辨认、风格适配和是否愿意用于活动，记录原始理由。采用隐藏方案名称的比较，避免技术标签影响选择。
- 每张发布样例的标题需逐字确认；活动事实与输入一致，不能以平均分掩盖单张错字。
- 至少有实际试用者认可的样例覆盖保留的各类风格；如果效果不能达到使用意愿，不将“新增了字体/接口”算作完成。
- 生成式路线若不可用，保留实验结论、明确展示人工标题导入和可控排版能力；主需求仍标为未完全满足，不能通过改名掩盖。

## 5. 团队审核与素材有效性

### 5.1 角色

只保留制作者、审核者和维护者三类职责，成员可兼任部分职责。发布审核由另一位成员执行，服务端校验身份与权限，不能依赖前端隐藏按钮或客户端自报角色。首期服务一个团队，采用简单账号管理，避免公开自助注册和复杂组织管理。

### 5.2 版本规则

- 活动事实修改生成修订号。海报绑定具体活动修订、知识发布批次、标题资产版本和渲染输入快照。
- 海报版本使用 draft / in_review / approved / rejected 等明确状态；提交后的版本不可原地覆盖，修改生成下一版本。
- 成品审核状态与有效性分开：曾被批准不代表当前仍然可用。
- 活动改期、改地点或取消后，旧素材在正式查询与正式下载入口立即失效。有效性检查基于当前活动修订执行，不依赖后台批量标记完成。
- 历史记录保留，具备权限的成员可以回看；历史查看与“获取当前正式素材”明确区分。
- 文件哈希、源资产版本和审核对象绑定，防止批准后换图仍沿用旧审核。
- 发布动作在同一事务中检查海报版本、活动修订和审批状态；活动改期与审批并发时，旧版本不能成为当前正式版。
- 重复提交和网络重试使用幂等键；相同请求返回已有结果，禁止重复发布或重复触发付费生成。

系统只能阻止平台继续将旧图作为正式素材提供，不能撤回已经下载或转发到外部的图片。对这类情况提供需要人工跟进的提示，不宣称自动撤回能力。

## 6. DesignHub 的知识发布

围绕少量有来源、能够解释设计选择的内容建设，避免单纯堆积卡片数量。

- 接入自有或获授权资料，保留来源位置与内容摘要；重复导入不重复建卡。
- 候选卡可以编辑、审核、驳回和停用；审核记录与发布结果分别保存。
- 发布使用独立版本：构建新索引 → 验证 → 切换当前批次。中途失败不影响上一可用批次。
- 检索固定到明确发布批次。索引不可用时，如果采用词法回退，也必须使用相同批次的数据和同一套有效性过滤。
- 明确停用的知识需要即时过滤，不能等待下一次完整索引重建后才退出新检索。
- 运行记录保存当时使用的知识版本和必要快照；旧结果可解释，新任务不会继续使用停用内容。历史追溯不等于允许被停用内容再次作为当前依据。
- 生成素材只有经过审核才能进入正式素材查询，不能自动升级为权威设计知识。

知识模块初期采用现有结构的兼容导入。文件、关系数据与向量索引各司其职，不把活动事实和审批状态当作向量检索的权威结果。

## 7. 预算与调用管理

人民币 50 元是整个升级验证与相关试用的累计付费上限，包含文本、生图、视觉校验以及可能被计费的失败调用和重试。此前历史费用不计入本轮，但本轮的所有实际调用必须登记。

建议分配：艺术标题可行性实验最多 10 元，集成与固定需求验证最多 20 元，试用最多 10 元，最终复现和异常补测预留 10 元。可以在总额内调整，不能提高总上限；这些数字是资源安排，不是生成次数承诺。

实施要求：

1. 在首个付费实验前核对所用服务和模型的当前单价、计费单位与账户情况；目前尚未确认，本文不估算能生成多少张。
2. 调用前按价格及请求上限预留额度，并在并发情况下原子扣减可用额度；如果无法给出保守上界，不发起该付费请求。
3. 限制 token、图片数量、生成尝试和重试；Provider 内部重试也必须进入同一计费记录。一次超时不能被当成免费失败后无限重发。
4. 区分已知实际费用、估算费用和待核对费用；对不确定费用保留预留额度，不能提前释放后继续花费。
5. 每次记录用途、任务、模型、尝试号、缓存命中、请求标识（若服务提供）和结果。账单核对后结算；未知费用不宣称为精确成本。
6. 同一业务操作的网络重试使用稳定幂等键复用原任务；不同成员或不同业务操作不自动合并任务。对于有权访问且文字、风格、模型、参数、版本等完整键一致的已有素材，可复用资产缓存，并在各自任务中保留操作人与复用记录。
7. 达到额度后停止新增付费调用，保留已有素材编辑、审核、检索等功能。配合服务商可用的账户限额，避免只靠前端提示。

后台状态流、权限、异常和并发主要用可替换依赖测试，不为每个后台场景反复真实生图。真实调用集中用于效果验证和少量端到端复现。

## 8. 三个最终演示场景

### A. 艺术标题退回修改

制作者生成活动海报 → 审核者发现标题难认或有错字 → 只重做标题 → 保留已确认背景与活动事实 → 再次提交并发布。

证据：同题前后图、图层差异、人工反馈、每轮费用、审核者和明确版本。

### B. 活动临时改期

活动从周五改到周六 → 旧正式图退出默认查询 → 复用标题和背景、仅修改日期 → 新版重新审核发布。

证据：旧版被正式入口阻断、历史仍可追溯、复用资产校验值不变、没有不必要的生图调用、重复与并发请求结果正确。

### C. 知识规范更新失败

维护者修改规范 → 新索引构建失败 → 旧批次继续可用 → 修复后重试发布 → 新任务使用新批次，旧任务可解释当时依据。

证据：失败发布状态、活动批次指针、检索引用版本、停用过滤、恢复记录。

## 9. 试用与求职证据

每名试用者完成少量清晰任务，记录是否完成、耗时、修改次数、失败情况、退回原因和实际采用意愿。真实活动与模拟验收单独标注，反馈按参与者编号保存，不收集不必要的个人信息。

预先固定指标口径并报告样本量：

- 标题错误样本数 / 全部尝试样本数，以及人工校对后的可发布样本数。
- 完成任务人数、任务总次数、失败次数与中位完成时间；如果没有同条件基线，就不写效率提升。
- 同题对照选择及原因；小样本结果按实际观察表述，不推广为普遍优于其他设计工具。
- 活动事实保持、改期阻断、权限拒绝、并发提交和知识发布故障的场景结果。
- 每个任务的实际/估算费用和重复资产利用情况；失败尝试必须进入分母。
- 对比评测保持信号与版本一致，缺失时明确标记不可比。DeepGaze 或模型审美分仅作辅助，不代替用户采用结果。

最终简历从这些记录中提取事实：业务问题 → 为什么这样设计 → 处理了哪些失败 → 真实试用结果。技术名词只保留能够在代码和演示中解释的部分。

## 10. 实施顺序与交付

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 1. 标题能力验证 | 当前路径基线、可控标题、生成式小样、对照记录 | 字体选择/回退可解释；真实试用者确认有愿意采用的手绘方向；失败边界清楚 |
| 2. 分层生成与团队素材流程 | 艺术标题资产、活动修订、角色、审核、正式查询和预算账本 | A/B 场景通过；成本受控；修改不会沿用错误的旧审核 |
| 3. 知识治理与可靠发布 | 来源、编辑审核、发布批次、停用和恢复 | C 场景通过；知识依据可追溯，失败不造成部分发布 |
| 4. 试用和完整验收 | 可运行版本、操作说明、反馈记录、回归结果 | 真实试用与模拟测试分别报告；缺陷和未完成项清楚 |
| 5. 求职材料 | 一页简历与可编辑源文件、演示案例、面试讲解 | 只写真实完成与验证的内容，技术取舍能对应代码与业务场景 |

预算保护的基础实现必须先于首次真实调用，不因上表将完整账本列入阶段 2 而延后。阶段 1 的艺术效果是优先门槛，其余后台工作可以先设计，但不能用后台完成度替代效果验收。

进入实施时继续保护当前未跟踪的 `docs/demo/photography-club-brief.json` 和 `scripts/run_readme_demo.py`，不覆盖已有工作。需要用户参与的下一次判断应基于具体标题样例和试用任务，不再要求用户代选框架与数据库。
