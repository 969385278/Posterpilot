# 海报案例 Wiki 数据说明

首批 11 张真实历史海报/海报设计稿，开发助手已逐张视觉检查；用户验收状态均为 pending。它们覆盖新艺术装饰、双色版画、冷暖配色、运动活动信息分组、几何文字与摄影拼贴。不是现代游戏海报数据集，也不声称风格覆盖完整。

## 文件职责

- `catalog.json`：API、页面 Wiki、Agent 案例检索与用户直接选择共享的数据源；不要维护第二份平行列表。
- `reviewed_features.json`：逐张视觉检查后的中文特点、使用限制和可执行近似预设，属于人工整理数据。
- `images/commons-*.jpg`：实际参考缩略图；保留来源图像，不自动裁切、抹水印或改图。
- `sources/commons-*.json`：取得时的 Wikimedia Commons imageinfo 原始元数据、来源 URL、取得时间和下载图像 SHA256。

## 取得和复核

在项目根目录运行：

```powershell
.venv\Scripts\python.exe scripts/prepare_case_assets.py --commons
.venv\Scripts\python.exe scripts/build_case_catalog.py
```

第一步只准备素材，不将下载成功等同于设计审查通过；第二步仅收录 `reviewed_features.json` 中已经检查的条目。脚本校验图像格式和哈希，不静默覆盖已存在的素材。外部网站不可用时保留错误，不制造替代来源。

12 张下载候选中，`commons-106991594.jpg` 是劳特累克相关素描，并非完成的海报，未加入 catalog。该素材和来源保留用于解释筛选过程，不出现在用户案例列表。

最初尝试的 Art Institute of Chicago 公有领域接口返回了作品元数据，但图片接口遇到访问限制；没有绕过验证，也没有将未取得/未检查的作品加入目录。

## 来源和权利边界

入选条目的 Wikimedia Commons 来源页均明确标注 Public domain，快照保留这一标注及原作者/原机构信息。来源页标注不是本项目做出的法律保证，商业复用需核对适用地区、原始机构说明以及可能存在的标识权利。页面提供逐张来源链接，不声称拥有作品版权。

图中的历史机构、品牌或政治标识仅作出处信息，不进入新海报活动事实，也不要求生图模型复制。外部字体名称不能可靠反推，所有字体描述均按视觉气质表达；颜色值为视觉近似。

## 为什么不是把 Wiki 替换为 RAG

设计原则 RAG 回答“什么规则在什么条件下适用”，案例 Wiki 回答“可以借鉴哪种视觉做法”。两者是不同数据类型：

- 用户明确选案例：按 ID 读取，不依赖向量检索是否命中；只投影勾选维度。
- Agent 查案例：`search_poster_cases` 使用文本二元片段与标签检索，不是图像向量相似检索。
- 案例检索结果含 case_id 和 source_url，不伪装成设计原则的 card_id。
- 一个维度只允许一个来源，最多三张参考，避免同一维度相互冲突。

## 可执行近似与不能照搬的部分

配色进入生图提示，不能保证每个像素精确匹配。字体气质映射到现有中文宋体/无衬线/粗体预设，实际渲染字体与字号会另行报告。文字构图映射到少量安全布局预设，同时背景提示参考所选构图；不复制任意坐标。信息层级可提供默认注意力优先级，用户显式设置优先。

不支持重建原图图层、任意旋转字形、精确复制手绘字体、增删背景人物或逐对象重绘。
